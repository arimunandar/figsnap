    The chat itself is the Agent tab in the code column, beside React and HTML.     What the agent can reach

    The chips on the composer are what travels with each message: names, types, sizes and node ids, never the design itself, which the agent fetches with a tool when it needs it. The list follows your canvas selection until you pin something with +, which is how two layers can be in front of the agent at once. + also attaches a file — an image, a PDF, a spec — where the harness says it can read one, and a render of the pinned layer goes along automatically to harnesses that read images.

    Type while it is answering and the message queues rather than being refused. A slash offers whatever commands the harness publishes, and the picker beside Send switches its own modes.

    Reading is always on: the selection, the layer tree, and the full extraction — the same HTML measured against what Figma draws, the same byte-exact figmaCss, images inlined and icons as real SVG. Nothing is truncated on the way, which is the difference between this and asking over a capped API.

    Edits in the Agent column decides whether the canvas can be touched at all; it starts off, and a harness told to skip its own permission prompts still cannot get past it. Who answers those prompts is a different question with no switch of its own: the harness's modes answer it where it publishes them, and otherwise the daemon answers for you, writes each one into the transcript, and puts the way back on that line.

    Each edit is committed as one undo step, so one Cmd-Z takes back one change. Ask for a checkpoint before a long run and you get a named version to return to. Both switches are remembered per user, so a session you set up once starts the same way next time.

    The same designs from a terminal

    The tools the in-panel agent uses are an MCP server, and nothing about it is private to this panel. Any MCP client on this machine can spawn it and reach the file you have open — Claude Code in a project, an editor, a script. One command, no configuration: the daemon listens on a fixed port and writes its token to ~/.figsnap/agent-token, and the server finds both. 

    claude mcp add figsnap -- npx -y figsnap-mcp

    Edits still gates it. An agent reaching in from a terminal gets the same read tools and the same refusal on the writing ones until you turn Edits on here, because that switch lives in the daemon rather than in any one client.

    Where the agent runs

    On your machine, as a subprocess of the daemon, using the login and billing you already have. This plugin never sees a model key. The directory above bounds the file reads and writes the daemon performs on the agent's behalf — but the agent also gets a terminal, and it runs as you. Treat starting a session as running that harness in that directory yourself, because that is what it is.

    The socket is guarded twice, because any page you visit can open a connection to a port on your own machine: the daemon checks the Origin of the handshake, which a browser cannot forge, and requires the token above, which a browser WebSocket cannot send in a header and so travels in the address.

    ⋯ → History lists earlier conversations, titled by the question that started each one and labelled with the harness, the folder and the file it belonged to. Opening one relaunches that harness in that folder and asks it to replay.

    A plugin exists only while you have it open — there is no background or scheduled mode, and closing it ends the session on this side. The session id is stored, so reopening asks the harness to replay the conversation rather than starting a new one. Figma can also take the plugin's runtime away on its own, mid-answer, which is the same case and has the same answer.

    Claude Code skill

    .claude/skills/figsnap/SKILL.md teaches an agent these endpoints, and figsnap-extractor is an agent that pulls several nodes and reports a summary rather than tens of kilobytes of CSS. Both are generated with this relay's address already in them.

    The relay serves them; it cannot write them, having no filesystem of its own. Two commands in the project you want them in: 

    mkdir -p .claude/skills/figsnap .claude/agents
curl -s RELAY/skill/SKILL.md > .claude/skills/figsnap/SKILL.md
curl -s RELAY/skill/figsnap-extractor.md > .claude/agents/figsnap-extractor.md

    Checking it from a terminal

    curl -s https://your-relay.workers.dev/health

    Running your own relay

    The address above is one deployment; yours is two commands, from the plugin's project directory: 

    npx wrangler login
npm run worker:deploy

    Signing in happens in this panel: Sign in at the top asks for an email and a password, stores the token it gets back, and brings the socket and the HTTP API up without another click. It is what the plugin opens with when no session is stored.

    The password is sent to your own relay over HTTPS and is never stored here — only the token it returns is, per user rather than in the project. The relay also serves /login as an ordinary web page if you would rather type the password into a browser, where a password manager can fill it.

    Each account gets its own room. A token reaches the designs of the plugin signed in with that same account and nobody else's, so several designers can share one relay without colliding. Passwords are stored as a chained PBKDF2 hash, tokens only as a SHA-256 hash, and signing in again issues a fresh token while older ones keep working until revoked. Your saved set is kept per account too, so it follows you between machines — node ids and layer names, never a design.

    A newly deployed address must be added to networkAccess.devAllowedDomains in manifest.json — the exact host, not a *.workers.dev wildcard, which would let this plugin reach every Worker on the internet — followed by a re-import. The address offered above is already listed.

    Two routes stay local-only on a hosted relay and answer 501: browsing directories and installing the Claude Code skill, both of which need a filesystem.

    The relay serves the whole manual over HTTP at /docs, and as Markdown at /docs.md for pasting into an agent.
